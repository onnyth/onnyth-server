# Entities

This complements `docs/data/database-schema.md` (which tracks tables/migrations) by describing what
each entity group is *responsible for* in domain terms, and the domain-model/entity split pattern used
throughout the codebase.

## Domain model vs. JPA entity

Every feature keeps two representations of the same concept:

- `domain/model/*.java` — framework-free, used by `application/usecase` and passed across port
  boundaries. Some are immutable records (e.g. `Bookmark`), some are mutable POJOs with Lombok
  `@Builder`/`@Getter`/`@Setter` (e.g. `User`) — mutability is a deliberate, documented choice where
  the use-case layer follows a mutate-then-save pattern.
- `adapter/out/persistence/*Entity.java` — JPA-annotated, mapped 1:1 to a table, never referenced
  outside that feature's own `adapter/out/persistence` package.

A `*PersistenceMapper` translates between the two; a `*RepositoryAdapter` is the only class that
touches both. See `docs/architecture/low-level-design.md`.

## Entity responsibility groups

| Group | Tables | Responsibility |
|---|---|---|
| **Identity** | `users` | The one aggregate every other feature reads/writes against — identity, gamification state (score/xp/level/rank/coins), active cosmetics, world/country rank, vote score. See `docs/features/users.md`. |
| **Onboarding** | `registration_drafts` | In-progress, multi-step onboarding state prior to commit into the structured stat tables. See `docs/features/registration.md`. |
| **Structured life stats** | `user_occupation`, `user_wealth`, `user_physique`, `user_wisdom`, `user_charisma`, `user_social_accounts`, `user_xfactors`, `user_education`, `profile_likes` | One table per real-world stat domain, each independently scored and independently owned by `lifestats/`. Supersedes the orphaned `life_stats`/`life_stat_history` generic model. See `docs/features/life-stats.md`. |
| **Scoring** | `score_history`, `sport_medals` | Historical score-change audit trail and sport/competition medals (a scoring input), owned by `scoring/`. See `docs/features/scoring.md`. |
| **Progression** | `user_streaks` (streak), `activity_types` + `activity_log` (activity), `quests` + `quest_completions` (quest), `achievements` + `user_achievements` + `user_displayed_achievements` (achievement), `cosmetic_items` + `user_cosmetics` (store) | Gamification content and the player's progress against it. Level/XP themselves are stored directly on `users` (`xp`, `level`), not a separate table — see `docs/features/leveling.md`, `docs/features/xp.md`. |
| **Social graph** | `friend_requests`, `friendships`, `follows` (unwired) | Bidirectional friendships (2 rows per friendship) plus a request/response workflow; `follows` exists but has no use case. See `docs/features/friendships.md`. |
| **Discovery / ranking** | `leaderboard_snapshots` | Point-in-time leaderboard position snapshots, scoped per friend-group owner. See `docs/features/leaderboard.md`. |
| **Timeline** | `feed_events` | Denormalized, JSON-payload event log consumed by the friend feed. See `docs/features/feed.md`. |
| **Profile presentation** | `profile_votes` | Peer upvote/downvote on a profile. See `docs/features/profiles.md`. |
| **Utility** | `bookmark` (+ `bookmark_tags`) | Standalone bookmark CRUD, unrelated to the gamification domain — the idempotency/Kafka reference feature. See `docs/features/bookmarks.md`. |
| **Orphaned** | `life_stats`, `life_stat_history` | No longer written by any code; kept only because no migration drops them. See `docs/development/known-issues.md`. |
| **Placeholder** | `posts`, `comments`, `likes` | JPA-mapped but have no service/controller/repository — reserved for a possible future social feature, not in-progress work. |

## Primary key convention

Every entity uses a `UUID` primary key. Most are auto-generated by the database/JPA
(`@GeneratedValue`); a few use a natural or composite key where that's the actual identity
(`registration_drafts.user_id` as PK, `profile_likes`' composite `ProfileLikeId`, `follows`' composite
`FollowId`).
